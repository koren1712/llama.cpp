Disk-backed Expert Streaming for Windows/CUDA

Status date: 2026-07-04

This report documents a local measurement campaign for GLM-4.5-Air Q4_K_M expert streaming in llama.cpp on a Windows/CUDA desktop. The optimized streaming path is measured on Windows/CUDA; non-Windows builds are untested. The branch adds file-offset registration for GGUF expert tensors, a persistent Windows read pool, pointer-returning streaming APIs, in-op read/compute overlap, slab-cache experiments, and VRAM expert spill experiments.

The streaming path reached the NVMe bandwidth range during generation. The remaining wall is bytes per token: the best pure streaming run read 132.045 GB / 32 = 4.13 GB/token. With four early expert blocks pinned in VRAM, disk traffic fell to 122.356 GB / 32 = 3.82 GB/token.

The earlier heap-LRU cache design also lost to copy and eviction overhead. The zero-copy slab avoids per-hit memcpy, but on this machine a large resident expert slab still competes with the OS, CUDA context, staging buffers, and file cache. The native reader also showed PCIe 3.0 storage throughput flattening near 2.38 GB/s for 16 MiB reads regardless of thread count.

Build and Run

git clone https://github.com/koren1712/llama.cpp.git
cd llama.cpp
git checkout expert-streaming-win

cmake -S . -B build-stream-cuda -G Ninja ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DGGML_CUDA=ON ^
  -DLLAMA_CURL=OFF

cmake --build build-stream-cuda --config Release --target llama-completion -j 8
$env:LLAMA_EXPERT_STREAMING='1'
$env:LLAMA_EXPERT_STREAM_CACHE_MB='0'
$env:LLAMA_EXPERT_STREAM_SLAB_MB='0'
$env:LLAMA_EXPERT_STREAM_PREFETCH_SLOTS='16'
$env:LLAMA_EXPERT_STREAM_POOL_THREADS='12'

.\build-stream-cuda\bin\llama-completion.exe `
  -m C:\llama\big-moe-q4.gguf `
  -ngl 12 `
  -ot "ffn_.*_exps=CPU" `
  -c 4096 -n 32 -p "hi" `
  --no-warmup --temp 0 -no-cnv --simple-io

Decision

The SSD streaming path is real on this machine, but this pass did not reach the original 1.5 t/s target. The best honest number for this model and hardware is 0.75 t/s. The practical next experiments are lower bytes per token, more physical RAM for cache-resident experts, or an execution plan that touches fewer expert tensors per token.

Scope: This report is local measurement data for a fork branch. It does not claim upstream suitability or general performance across hardware.
